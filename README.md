## تحديث سابق — تصحيح مشكلة الـ Build على Vercel

لو ظهرلك وقت الـ Deploy على Vercel خطأ زي:
```
Error: supabaseKey is required.
Error: Failed to collect page data for /api/admin/clients/create
```
السبب إن متغير `SUPABASE_SERVICE_ROLE_KEY` مش مضاف في إعدادات Vercel (مش
كفاية إنه موجود في `.env.local` عندك بس — الملف ده ملفك الشخصي ومبيتنشرش
مع المشروع). خطوات الحل:

1. روح Supabase Dashboard → Project Settings → API → انسخ قيمة **service_role**.
2. روح مشروعك في Vercel → **Settings → Environment Variables** → أضف:
   - `NEXT_PUBLIC_SUPABASE_URL` (لو مش مضاف بالفعل)
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` (لو مش مضاف بالفعل)
   - `SUPABASE_SERVICE_ROLE_KEY` ← القيمة اللي نسختها من فوق
   - اختار الثلاثة يتفعّلوا على Production + Preview + Development.
3. بعد الإضافة، لازم تعمل **Redeploy** (مش هيتفعّل تلقائي على الـ deployment
   القديم — من تبويب Deployments → آخر Deployment → ⋯ → Redeploy).

كمان صلّحت الكود نفسه عشان حتى لو حد نسي يضيف المتغير، الـ build مايقعش
بالكامل — هيبقى بس المسارات المرتبطة بتبويب "إدارة العملاء" هي اللي ترجع
رسالة خطأ واضحة وقت الاستخدام الفعلي بدل ما توقف نشر الموقع كله.

## تحديث سابق — المنشورات: جدولة + تثبيت + صور متعددة + إشعار تلقائي

قسم "🖼️ المنشورات" (تبويب "🗂️ المحتوى") بقى فيه:
- **الكابشن، المحتوى الكامل، التصنيف، الوسوم** — حقول منفصلة زي ما طلبت.
- **صور إضافية** غير صورة الغلاف (معرض صور للمنشور الواحد).
- **📌 تثبيت المنشور** — بيظهر فوق كل المنشورات التانية (عند العميل والزوار).
- **⏰ جدولة النشر** — تحدد تاريخ ووقت مستقبلي، والمنشور مش هيظهر لحد ما
  الوقت ده يجي (لو سيبتها فاضية، بيتنشر فورًا زي ما هو دلوقتي).
- **إشعار تلقائي لكل العملاء** بمجرد ما المنشور يبقى "منشور" لأول مرة (سواء
  عند الإنشاء، أو تعديل حالته من مسودة/مخفي لمنشور).

خطوة SQL واحدة مطلوبة: نفّذ `sql/patch_social_posts_extra.sql` في Supabase
SQL Editor (بعد migration_content.sql).

## تحديث سابق — تبويب "🔔 الإشعارات" (إرسال للكل + جدولة)

تبويب جديد باسم **"🔔 الإشعارات"** بيدّيك:
- إرسال إشعار لعميل واحد محدد، أو لكل العملاء دفعة واحدة بضغطة زر.
- جدولة الإشعار ليظهر في تاريخ ووقت مستقبلي (اسيب الحقل فاضي عشان يتبعت فورًا).
- تعديل أو حذف أي إشعار — ولو كان إشعار "لكل العملاء"، تقدر تعدّله أو تحذفه
  كمجموعة واحدة من غير ما تدوّر على كل نسخة صف صف.

خطوة SQL واحدة مطلوبة: نفّذ ملف `sql/patch_notifications_broadcast.sql` في
Supabase SQL Editor (بعد migration_client_portal.sql).

ملحوظة: قسم "الإشعارات" اللي كان جوه تبويب "🗂️ بيانات لوحة العميل" القديم
اتشال، لأن التبويب الجديد بيغطي نفس الوظيفة وأقوى منه (إرسال جماعي + جدولة).

## تحديث سابق — تبويب "👥 إدارة العملاء" الكامل

في لوحة السوبر أدمن دلوقتي تبويب جديد اسمه **"👥 إدارة العملاء"** بيدّيك تحكم
كامل في حسابات العملاء: إضافة عميل جديد، تعديل بياناته (حتى الإيميل)، حذف
الحساب نهائيًا، تفعيل/إيقاف الحساب (بيمنعه من تسجيل الدخول تمامًا)، إعادة
تعيين كلمة المرور مباشرة من غير ما تستنى العميل، وسجل نشاط لكل عميل.

عشان يشتغل لازم خطوتين إضافيتين (مرة واحدة بس):

1. **SQL:** روح Supabase Dashboard → SQL Editor → New Query، ونفّذ ملف
   `sql/patch_clients_admin.sql` (بعد ما تكون نفّذت schema.sql و
   migration_clients.sql و migration_analytics.sql قبل كده).
2. **متغير بيئة سري:** بعض العمليات (إنشاء/حذف حساب، تغيير كلمة المرور،
   تفعيل/إيقاف) لازم مفتاح `service_role` من Supabase (صلاحية كاملة، سيرفر
   بس ومحدش يشوفه في المتصفح). روح Supabase Dashboard → Project Settings →
   API → انسخ قيمة **service_role**، وحطها في `.env.local`:
   ```
   SUPABASE_SERVICE_ROLE_KEY=القيمة-هنا
   ```
   ⚠️ المفتاح ده قوي جدًا — لا تشاركه مع حد، ولا تحطه أبدًا في متغير بادئته
   `NEXT_PUBLIC_` (وقتها هيبان في كود المتصفح لأي زائر). لو بتنشر على Vercel،
   ضيفه من Project Settings → Environment Variables هناك برضه.

## تحديث سابق — بيانات لوحة العميل بقت حقيقية

كل أقسام لوحة تحكم العميل (الرئيسية، الأداء، الحملات، التقارير، الملفات،
السكربتات، الملاحظات، الفواتير، الإشعارات) بقت بتقرأ من Supabase بدل البيانات
التجريبية. عشان تشتغل:

1. روح Supabase Dashboard → SQL Editor → New Query.
2. نفّذ ملف `sql/migration_client_portal.sql` كامل (بعد ما تكون نفّذت
   `schema.sql` و `migration_clients.sql` و `migration_analytics.sql` قبل كده).
   الملف ده كمان بينشئ Storage Bucket اسمه `client-files` عشان رفع الملفات
   الحقيقي (مش رابط يدوي).
3. في لوحة السوبر أدمن هتلاقي تبويب جديد اسمه **"🗂️ بيانات لوحة العميل"** —
   منه تختار عميل، وتختار قسم (زي "الحملات الإعلانية" أو "الفواتير")، وتضيف/
   تعدّل/تحذف/تنشر البيانات بتاعته. الصفوف "منشورة" بس هي اللي تظهر للعميل،
   تقدر تحضّر بيانات كمسودة وتنشرها لما تجهز. في قسم "الملفات" تقدر ترفع
   الملف مباشرة من جهازك (PDF/صورة/فيديو/إكسل) بدل كتابة رابط يدوي.
4. تبويب "📈 تحليلات العملاء" الموجود أصلًا فضل زي ما هو من غير تغيير.
